Building QuickFIX

Building with CMake (Recommended)

QuickFIX uses CMake as its primary build system, providing consistent builds across all platforms.

Prerequisites

  • C++17 compatible compiler (GCC 7+, Clang 5+, MSVC 2017+)
  • CMake 3.5 or higher
  • Optional: OpenSSL for SSL/TLS support
  • Optional: MySQL, PostgreSQL, or ODBC client libraries

Windows

Basic Build:

mkdir build
cd build
cmake -G "Visual Studio 17 2022" -A x64 ..
cmake --build . --config Release
cmake --install . --config Release

With SSL Support:

mkdir build
cd build
cmake -G "Visual Studio 17 2022" -A x64 ^
  -DHAVE_SSL=ON ^
  -DOPENSSL_ROOT_DIR="C:\path\to\openssl" ^
  -DCMAKE_INSTALL_PREFIX="C:\quickfix" ..
cmake --build . --config Release
cmake --install . --config Release

With Database Support:

cmake -G "Visual Studio 17 2022" -A x64 ^
  -DHAVE_MYSQL=ON ^
  -DHAVE_POSTGRESQL=ON ^
  -DHAVE_ODBC=ON ..
cmake --build . --config Release

Supported Visual Studio versions: VS 2017, VS 2019, VS 2022


Linux / macOS

Basic Build:

cmake -DCMAKE_BUILD_TYPE=Release .
make -j$(nproc)
sudo make install

With SSL Support:

cmake -DCMAKE_BUILD_TYPE=Release -DHAVE_SSL=ON .
make -j$(nproc)
sudo make install

With Database Support:

cmake -DCMAKE_BUILD_TYPE=Release \
  -DHAVE_MYSQL=ON \
  -DHAVE_POSTGRESQL=ON .
make -j$(nproc)
sudo make install

Custom Installation Directory:

cmake -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX=/usr/local .
make -j$(nproc)
sudo make install

For an out-of-source build such as cmake -S . -B build, generated headers and default outputs remain under the build tree: libraries and executables use build/lib, example links use build/bin, and test links use build/test. QUICKFIX_LIB_OUTPUT_DIR still overrides the library/runtime directory. Autotools supplies QUICKFIX_TEST_SRCDIR and QUICKFIX_TEST_BUILDDIR when its legacy test scripts run from a separate build tree; direct script callers must supply the same two paths.

CMake Build Options

Option Description Default
-DHAVE_SSL=ON Enable SSL/TLS support (requires OpenSSL) OFF
-DHAVE_MYSQL=ON Enable MySQL message store support OFF
-DHAVE_POSTGRESQL=ON Enable PostgreSQL message store support OFF
-DHAVE_ODBC=ON Enable ODBC message store support OFF
-DHAVE_PYTHON3=ON Build Python 3 bindings OFF
-DQUICKFIX_SHARED_LIBS=ON Build shared libraries instead of static ON
-DQUICKFIX_EXAMPLES=ON Build example applications ON
-DQUICKFIX_TESTS=ON Build test suite ON
-DCMAKE_BUILD_TYPE=Release Build type (Debug, Release, RelWithDebInfo) -
-DCMAKE_INSTALL_PREFIX=/path Installation directory /usr/local

Building with Autotools (Alternative)

QuickFIX also supports traditional autotools-based builds on Unix-like systems.

Linux / macOS

./bootstrap
./configure
make
make check
sudo make install

You can run configure with the --prefix=<base directory> option to install to a custom location.


Installed Infinite C ABI

By default, the static build installs quickfix/InfiniteFrameAdapter.h, libquickfix.a, and the stock QuickFIX dictionaries under share/quickfix. The production Infinite RFQ profile remains unavailable in this ordinary mode; stock dictionaries are not a production substitute.

A self-contained Linux amd64 archive can instead embed the exact custom INFINITE-FIXT11 and INFINITE-RFQ-1.0.0-EP299 dictionaries:

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DHAVE_SSL=OFF \
  -DQUICKFIX_SHARED_LIBS=OFF -DIRFQ_INFINITE_EMBED_DICTIONARIES=ON

This opt-in profile requires the pinned Linux amd64 GCC/G++ 13.3.0 and GNU objcopy/ld 2.42 route. Configuration verifies both XML files and their provenance, license inventory, and source license by exact size and SHA-256 before generating two read-only, non-executable-stack resources with local boundary symbols. These governed inputs remain source-distribution evidence and are not installed. The resulting archive does not read dictionaries from a runtime path.

The embedded build exposes an explicit infinite_adapter_package target. It derives the source commit, tree, merge base, and canonical binary diff SHA-256 from the clean /src Git checkout and the pinned release base. Packaging therefore requires complete, readable Git metadata; source tarballs, shallow or promisor checkouts, missing reachable objects, checkout-local Git info attributes, special index flags, and tracked, untracked, or ignored changes are rejected. Configure the accepted specification commit, tree and semantic bundle SHA-256, build image name and digest, and the path-independent build command through the corresponding IRFQ_INFINITE_* CMake cache values. Packaging is available only in the governed container after configuring /src into /build; invoke the target with:

cmake --build /build --parallel 2 --target infinite_adapter_package

The target fails closed when any identity is absent or invalid. It also requires the governed container paths /src, /build, and /build/out, the explicit /usr/bin/gcc-13 and /usr/bin/g++-13 compilers and canonical /usr/bin Ninja/binutils tools (including ar and ranlib), the default CMake Release flags, and no extra compiler or static-linker flags. The recorded build command must equal that canonical configure and two-job package-target invocation exactly. The target writes only /build/infinite-adapter-package/, containing libquickfix.a, InfiniteFrameAdapter.h, infinite-frame-adapter-abi.v2.tsv, LICENSES.txt, and manifest.sha256. The package preserves source artifact and license bytes, including the distinct QuickFIX, FIX dictionary, double-conversion, pugixml, and scope_guard notices. It is validated before publication and is not installed by cmake --install.

A C17 consumer must include the installed header, statically link libquickfix.a (using the C++ linker or its required C++ runtime libraries). ABI v2 exposes exactly seven semantic calls: scan, session_create, prepare, resume, apply_committed, abort, and destroy. Initialize every request and response header with its structure size and ABI version. Input is borrowed for one call and output is written only to caller-owned bounded buffers; a short buffer reports the exact required capacity without changing session state.

An application-dispatch REJECT resume must supply a gateway_inbound_disposition_id of 1–64 visible ASCII bytes. The slice is borrowed only for that call and is copied into tag 20003 of the governed BusinessMessageReject; every other resume must supply exactly {NULL, 0}. The adapter derives optional tag 379 from the validated inbound message and never retains the caller pointer.

The session handle is exclusively owned. Calls for one handle must not overlap, ownership may move between threads only after the previous call has joined, and destroy must not race another call. The adapter keeps only disposable session cache state and one bounded pending plan. It performs no transport, TLS, durable-store, callback, gate, or fence operation. The Rust gateway owns those responsibilities and supplies typed bounded inputs when resume requests store data or an explicit decision.

The embedded adapter artifact requires HAVE_SSL=OFF; Rust owns TLS. Session creation accepts authenticated identity and profile digests plus the already-validated native snapshot bytes. apply_committed installs only an exact, already-durable successor snapshot after checking its revision and domain-separated SHA-256. No legacy compatibility or callback bridge is installed.

Enable SSL support, optionally specify OpenSSL installation path

Testing Your Build

With CMake:

cmake --build . --target test
# or
ctest

With Autotools:

make check

Using vcpkg

QuickFIX is available via the vcpkg package manager:

git clone https://github.com/Microsoft/vcpkg.git
cd vcpkg
./bootstrap-vcpkg.sh  # Windows: bootstrap-vcpkg.bat
./vcpkg integrate install
./vcpkg install quickfix

Troubleshooting

  • Ensure your compiler supports C++17
  • For SSL issues, verify OpenSSL is properly installed and OPENSSL_ROOT_DIR is set correctly
  • For database support, ensure client libraries are installed and in the library path
  • On Windows, run CMake from the "Developer Command Prompt for Visual Studio"
  • Check the GitHub Issues page for known build problems
